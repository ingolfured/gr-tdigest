# Exact numerical reference

`bindings/python/tests/data/upstream_numerical_golden.json` contains 70 cases
generated by `generate.rs` against an independently built copy of G-Research
tdigest-rs commit `8d9cf1fe82c5c9254e5dc9593f01717e317f4333`, using Rust 1.90.0
on Linux x86_64. Source contents were checked against the upstream Git blobs;
the arithmetic files match `src/upstream/PROVENANCE.md` after reversing
the three documented namespace-only import changes.

The fixtures contain centroid means, integer weights, median, 11 quantile probes,
and 6 trimmed-mean intervals per case. Both precisions exercise delta 10/30/300,
ties, signed zero, tiny values, non-finite input, large uint32 weights, merge,
update, and the original default-delta reconstruction for copy/pickle/dict.
Expected floating results are f64 bit strings (f32 results widened exactly).
Tests compare finite values and infinities bit-for-bit; NaN payload/sign are
not part of the contract. No numerical tolerance is used.

To regenerate, build `generate.rs` as a standalone Cargo binary with
`serde_json = "1"` and a path dependency on an independent checkout of that
exact upstream `tdigest_core`, not on this replacement. Keep its four numerical
source files unchanged; the original Python wrapper reconstructs copies through
`from_means_weights(..., delta=300)` as encoded in the generator. Capture stdout
to the fixture and review any differences. The golden file SHA-256 is:

`517ec82ec124e55920c7049a95f0eb0c9f3e96cf60b4ee7d4457bf31b7a98560`

The gate also checks that all four original numerical source files and the
public Python wrapper remain unchanged. A finite fixture set is regression
evidence, not a mathematical proof for every possible input or platform.
